## The current experience

The general [autonomous task engine](autonomous-tasks.md) adds saved manager decisions, questions/answers, action receipts, separate verification, interruption/resume and exact-approved project-check coordination. Windows/Android have a task panel. Its adapters support public research, already-approved local previews, requested Gmail/Calendar reads and selected-project text. A fresh read or successful command is not proof of an arbitrary completed objective; current outcomes remain reviewable. Universal Windows control and authenticated online form automation remain unfinished.

You speak to one Nakama persona. Its fast interaction assignment starts at **Astra 6 low** and is independent of the deeper saved roles. Supported local greetings, time/date, timers, board, memory, status and navigation commands avoid a model call. Android greeting/time/timer requests are handled on the phone before any PC connection. More detailed work uses appropriate saved roles. Model response times still depend on the official client and account; no instantaneous-response benchmark has passed.

The new **Agent office** on Windows and Android displays named GPT/Claude workers at selectable desks. Green/orange provider colours also have text labels. Names and parent/child relationships come from persisted task/workflow identities, and the screens show recorded status and available output. Workflow orchestration is distinguished from an actual model request. See [the office guide](agent-office.md).

Managed project builds retain Astra/Fable planning and review, manager-relayed questions and Opus implementation. Required questions block development. After workers save files, supported root npm checks require exact PC approval; actual failure diagnostics return to Opus within the shared repair limit. Each repaired round requests fresh approvals before both independent reviews. No-script projects remain explicitly static-only. Stale source, rejected/expired approvals, unavailable tooling, interruption and revocation stop progress. Requested Ultracode maps to xhigh with Nakama orchestration; native Claude dynamic delegation remains disabled. [Project workflow](project-workflow.md).

## What is not a release promise

- No measured claim of maximum accuracy, the fastest model or near-instant AI answers.
- No unrestricted autonomous phone/browser operation or phone-screen streaming.
- No fully autonomous build/test/install/deploy loop, native Ultracode delegation or general Git merge management.
- No ChatGPT image-file generation, automatic Claude quota import or complete Kling media suite.
- No remote phone approval of PC-only deployments/deletion/commands/video.
- No production signing, unattended self-installation, automatic state rollback or public-ready release.

The clean public source snapshot excludes private history and personal artifacts. Production signing, full binary notices and installed recovery still require the gates in [release signing](release-signing.md).

## How to judge this build

Read [verification](verification.md) for completed host, native UI, Android and package checks. Synthetic fixtures do not establish live account eligibility, microphone quality, GPS, alarm sound or actual remote-input behaviour. No real messages, calls, purchases, paid generation or deployments are performed as development tests.

Use [the testing guide](testing-guide.md) and [editable checklist](feature-checklist.md) for your own acceptance. The checklist has **222 fields across 23 pages**, including website setup, browser, delivery, reports, general tasks and local preparation. The ignored personal PDF retains saved values; new boxes are unchecked. The separately distributed [public PDF template](assets/Nakama-Test-Checklist.pdf) is blank. Private acceptance values are not published.
